# Зеркальные запросы через компанию группы

Решение владельца 10.11.2026: вариант Б — зеркальные звенья по маршруту внутри основной сделки. Сфера — ГШО и запчасти; этот документ ведётся по мере внедрения.

## Как это работает (ГШО — PR 1)

1. Менеджер на вкладке «Позиции и характеристики» выбирает поставщика «Альянс-Импекс» (компанию группы: в карточке поставщика тип «компания группы», привязано юрлицо) и одного или нескольких конечных поставщиков.
2. По каждому конечному поставщику X в сделке создаётся пара записей «ответов завода»:
   - **U** — предложение Альянс-Импекс → Берг-Хаус;
   - **L** — запрос Альянс-Импекс → X.

   Запрос L уходит от имени Альянс-Импекс, с её почты и WeCom. Файл запроса сохраняется в папку сделки 01.
3. Ответ X вносится в L: цену, срок и модель — кнопкой «ответ поставщика», параметры — импортом файла с выбором «ответ: X (через Альянс-Импекс)».
4. Система сама пересчитывает U:
   - цена X → наценка Альянс-Импекс по действующей политике наценок группы → цена в валюте и на условиях последней ступени маршрута;
   - параметры, срок, фото и условия оплаты берутся из ответа X;
   - каждая новая цена — новая редакция.
5. В «Заводах и ответах» сравниваются и отбираются предложения U. При отборе:
   - позиция сделки получает цену Альянс-Импекс — она становится «ценой завода» в расчёте;
   - L тоже отмечается отобранным;
   - цена X записывается в историю цен поставщика с отметкой «через компанию группы».
6. Если ответ X изменился после отбора, цена в сделке молча не меняется: предложение помечается «ответ поставщика изменился после отбора», КД получает уведомление.

Отдельных сделок для компаний группы нет: все звенья живут внутри основной.

## Решения

| № | Решение |
|---|---|
| D-150 | Модель: пара `FactoryOffer` U/L в той же сделке. У U заполнены `end_supplier_id`, `route_id`, `chain`, `mirror_state`, `revision`, `transfer_price`; у L — `mirror_of_id` → U. Обычные ответы заводов и поиски «ответ завода позиции» зеркальные записи не затрагивают. Позицию, взятую из U, правка таблицы характеристик не превращает в обычный ответ. |
| D-151 | Каналы компании группы: `LegalEntity.channels = {mail_profile, mail_from, wecom_profile}`. Секреты — в переменных окружения `MAIL_PROFILE_<P>_SMTP_HOST/PORT/USER/PASSWORD/FROM` и `WECOM_PROFILE_<P>_CORP_ID/AGENT_ID/SECRET`. Каналы Берг-Хауса не подставляются: если профиль не настроен — «не отправлено: почта «…» не настроена», файл можно скачать и отправить вручную. На стенде (`MAIL_PROVIDER=console`) — консоль. |
| D-152 | Право «Цепочка компаний группы» (`intragroup_chain`) — КД, ФД, ЗГД, логист. Оно даёт видеть цену конечного поставщика, ступени, наценки и маржу группы, а уровень «правка» — вносить цену конечного поставщика. Менеджер и юрист видят предложение компании группы: имя конечного поставщика и параметры — да, цену поставщика и цепочку — нет. Цену самой компании группы видят те, у кого есть «История цен завода» или «Цепочка». |
| D-153 | Наценки на ГШО — в той же версионной политике наценок группы (визы ЗГД и ФД): `gsho_default`, `gsho_by_machine_type`, `gsho_by_supplier`. Приоритет: поставщик → тип машины → ставка по умолчанию. Без ставки ГШО предложение не рассчитывается («нет ставки наценки на ГШО»): ставки запчастей на технику не переносятся. |
| D-154 | Маршрут выбирается автоматически: активный, первая ступень — покупатель компания группы, последняя — компания, продающая клиенту. Приоритет — по стране поставщика, затем самый короткий. Нет маршрута → 409 с подсказкой, где его завести. Курсы — последние курсы ЦБ (как для запчастей), фиксируются в снимке цепочки вместе с версией политики. |
| D-155 | ФД или ЗГД может зафиксировать трансфертную цену компании группы (с основанием) вместо наценки и снять фиксацию; после отбора — нельзя. Изменение ответа поставщика после отбора помечается без изменения сделки, с уведомлением КД. |
