# Зеркальные запросы через компанию группы

Решение владельца 10.11.2026: вариант Б — зеркальные звенья по маршруту внутри основной сделки. Сфера — ГШО и запчасти; этот документ ведётся по мере внедрения.

## Как это работает (ГШО — PR 1)

1. Менеджер на вкладке «Позиции и характеристики» выбирает поставщика «Альянс-Импекс» (компанию группы: в карточке поставщика тип «компания группы», привязано юрлицо) и одного или нескольких конечных поставщиков.
2. По каждому конечному поставщику X в сделке создаётся пара записей «ответов завода»:
   - **U** — предложение Альянс-Импекс → Берг-Хаус;
   - **L** — запрос Альянс-Импекс → X.

   Запрос L уходит от имени Альянс-Импекс, с её почты и WeCom. Файл запроса сохраняется в папку сделки 01.
3. Ответ X вносится в L: цену, срок и модель — кнопкой «ответ поставщика», параметры — импортом файла с выбором «ответ: X (через Альянс-Импекс)».
4. Система сама пересчитывает U:
   - цена X → наценка Альянс-Импекс по действующей политике наценок группы → цена в валюте и на условиях последней ступени маршрута;
   - параметры, срок, фото и условия оплаты берутся из ответа X;
   - каждая новая цена — новая редакция.
5. В «Заводах и ответах» сравниваются и отбираются предложения U. При отборе:
   - позиция сделки получает цену Альянс-Импекс — она становится «ценой завода» в расчёте;
   - L тоже отмечается отобранным;
   - цена X записывается в историю цен поставщика с отметкой «через компанию группы».
6. Если ответ X изменился после отбора, цена в сделке молча не меняется: предложение помечается «ответ поставщика изменился после отбора», КД получает уведомление.

Отдельных сделок для компаний группы нет: все звенья живут внутри основной.

## Решения

| № | Решение |
|---|---|
| D-150 | Модель: пара `FactoryOffer` U/L в той же сделке. У U заполнены `end_supplier_id`, `route_id`, `chain`, `mirror_state`, `revision`, `transfer_price`; у L — `mirror_of_id` → U. Обычные ответы заводов и поиски «ответ завода позиции» зеркальные записи не затрагивают. Позицию, взятую из U, правка таблицы характеристик не превращает в обычный ответ. |
| D-151 | Каналы компании группы: `LegalEntity.channels = {mail_profile, mail_from, wecom_profile}`. Секреты — в переменных окружения `MAIL_PROFILE_<P>_SMTP_HOST/PORT/USER/PASSWORD/FROM` и `WECOM_PROFILE_<P>_CORP_ID/AGENT_ID/SECRET`. Каналы Берг-Хауса не подставляются: если профиль не настроен — «не отправлено: почта «…» не настроена», файл можно скачать и отправить вручную. На стенде (`MAIL_PROVIDER=console`) — консоль. |
| D-152 | Право «Цепочка компаний группы» (`intragroup_chain`) — КД, ФД, ЗГД, логист. Оно даёт видеть цену конечного поставщика, ступени, наценки и маржу группы, а уровень «правка» — вносить цену конечного поставщика. Менеджер и юрист видят предложение компании группы: имя конечного поставщика и параметры — да, цену поставщика и цепочку — нет. Цену самой компании группы видят те, у кого есть «История цен завода» или «Цепочка». |
| D-153 | Наценки на ГШО — в той же версионной политике наценок группы (визы ЗГД и ФД): `gsho_default`, `gsho_by_machine_type`, `gsho_by_supplier`. Приоритет: поставщик → тип машины → ставка по умолчанию. Без ставки ГШО предложение не рассчитывается («нет ставки наценки на ГШО»): ставки запчастей на технику не переносятся. |
| D-154 | Маршрут выбирается автоматически: активный, первая ступень — покупатель компания группы, последняя — компания, продающая клиенту. Приоритет — по стране поставщика, затем самый короткий. Нет маршрута → 409 с подсказкой, где его завести. Курсы — последние курсы ЦБ (как для запчастей), фиксируются в снимке цепочки вместе с версией политики. |
| D-155 | ФД или ЗГД может зафиксировать трансфертную цену компании группы (с основанием) вместо наценки и снять фиксацию; после отбора — нельзя. Изменение ответа поставщика после отбора помечается без изменения сделки, с уведомлением КД. |

## Запчасти — PR 2

1. В заявке на запчасти менеджер отмечает строки, выбирает «Альянс-Импекс» и под ним — одного или нескольких конечных поставщиков.
2. По каждому поставщику X создаются два запроса цен по тем же строкам:
   - U — предложение Альянс-Импекс → Берг-Хаус (русский, не отправляется);
   - L — запрос Альянс-Импекс → X на языке X.
3. «Отправить» в U отправляет L с почты и WeCom Альянс-Импекс.
4. Ответ X (вручную или из файла) вносит КД (или ЗГД) в L. Строки U пересчитываются: наличие, срок, партия, аналог — как у X; цена — по маршруту с наценками группы на запчасти, в валюте последней ступени.
5. В сравнении менеджер видит только U. КД, ФД, ЗГД и логист видят ещё ответ X и цепочку (L выбрать нельзя).
6. Выбор U ставит в строку заявки поставщика X, маршрут через Альянс-Импекс и цену X. Поэтому себестоимость строки совпадает с ценой Альянс-Импекс в рублях. Заказ поставщику (X → Альянс-Импекс) и внутригрупповые заказы строятся уже существующим механизмом маршрута. Менеджер в строке видит Альянс-Импекс и её цену.

| Код | Решение |
|---|---|
| D-156 | Модель: пара `SupplierRfq` U/L — так же, как D-150 для ГШО. У U: `supplier_id` = компания группы, `end_supplier_id`, `route_id`, `mirror_state`, `chain`; у L — `mirror_of_id` → U. Строки сопоставляются по номеру, у строки U в `chain` — цена X, ступени, маржа группы. Миграция `009`. |
| D-157 | Наценки — ставки запчастей той же политики группы (`default`, `by_group`, `by_supplier`); без утверждённой политики U не рассчитывается. Трансфертной цены для запчастей нет: строк много, и при необходимости ставка задаётся исключением по поставщику. |
| D-158 | Права: запрос L, его цены и ввод ответа — при праве «Цепочка компаний группы»; ФД и логист видят пары в списке запросов и сравнении. Обычные запросы — как раньше (менеджер, закупки, КД, ЗГД). Ручная смена поставщика в строке на ту же компанию группы или того же X связь не снимает; на другого — снимает. |
| D-159 | Изменение ответа X после выбора цену в заявке не меняет: у строки U отметка «новая цена — выберите повторно», уведомление КД. Повторный выбор принимает новую цену. Напоминание о сроке ответа — по L (U в напоминаниях не участвует). Закрытие закрывает пару. |

## Договоры и маржа группы — PR 3

1. **Маржа группы на «Расчёт и утверждение».** Если позиция взята из предложения компании группы, под маржой сделки появляется блок «Через компанию группы»: цена поставщика, цена компании группы («Цена завода» сделки), маржа группы на единицу и всего. По предложению считается: прибыль сделки + маржа группы = прибыль группы.
2. **Договор компании группы с конечным поставщиком.** Пакет закупки у Альянс-Импекс сразу формирует и пакет «Альянс-Импекс ← поставщик X» по ответу X. В нём покупатель — юрлицо Альянс-Импекс (её профиль и счёт), цена, валюта, базис, срок и график оплаты — из ответа X, позиции, характеристики и ЗИП X — из сделки. Пакет создаёт проект договора в реестре от имени Альянс-Импекс (нумерация её юрлица); дальше — обычный маршрут согласования и подписания. Если пакет X сформировать не удалось (нет реквизитов, ЗИП X не подтверждён), основной пакет всё равно формируется, а в ответе — что не так; пакет X можно сформировать в мастере позже.

| Код | Решение |
|---|---|
| D-160 | Договор компании группы с X — `LegalPackage` и `Contract` той же сделки, отметка `Contract.mirror_kind = via_group` и `snapshot.mirror`. Позиции — `MirrorPosition`: позиция сделки с ценой, валютой, базисом, сроком и оплатой из ответа X. Номер договора сделки с заводом в пакет X не подставляется, а его подписание реквизиты договора сделки не меняет. Шаблоны — те же, что выбраны для основного пакета. Миграция `010`. |
| D-160а | Видимость: договор и пакет компании группы с X (с ценой X) видят роли с правом «Цепочка компаний группы» и юрист — он проверяет договор (решение владельца). Менеджер их не видит и сам не формирует; автоматическое формирование вслед за его пакетом с компанией группы — допускается. В сделке и расчётах юрист, как и прежде, видит только цену компании группы. |
| D-161 | Маржа группы в расчёте сделки — ключ `group_chain` ответа `/calc`, только при праве «Цепочка компаний группы». Маржа — из снимка цепочки предложения компании группы (с трансфертной ценой, если она зафиксирована). |

## Внутригрупповые расчёты в «Финансах» — PR 4

## Правила цепочек: менеджер выбирает конечного поставщика — PR 5

1. **Правила по умолчанию** — «Настройки → Ставки и нормативы → Правила внутригрупповых цепочек». Ведут ФД и ЗГД: вид сделки (ГШО, запчасти, сервис, любая), страна поставщика или конкретный поставщик → маршрут через компанию группы или «напрямую от Берг-Хауса».
2. **Менеджер выбирает конечного поставщика** (компании группы в его списке нет). Запрос сразу уходит по правилу: через компанию группы — с её почты и WeCom (пара U/L, как в PR 1–2), без правила — напрямую.

4. **Виза до КП.** Если в сделке есть позиции через компанию группы, без визы ФД или ЗГД на цепочку нельзя отправить расчёт на утверждение и сформировать, отправить или отметить отправленным КП; в заявке на запчасти — сформировать КП со строками через компанию группы. Цепочка изменилась после визы (маршрут, компания, трансфертная цена) — нужна новая.
