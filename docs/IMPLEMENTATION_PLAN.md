# План внедрения и состояние проекта

Ориентир ТЗ: три очереди, 5–7 месяцев, команда 3–4 человека (backend, frontend, аналитик/QA, DevOps на часть времени).

## Что уже реализовано в этом репозитории (каркас очереди 1)

| Область ТЗ | Состояние | Где |
| --- | --- | --- |
| Модель себестоимости: 14 статей × 3 сценария, уровни позиция/вариант/сделка, распределение статей партии, накладные по шкале, маржа/наценка/прибыль, чувствительность, подбор цены по марже и наценке | готово, покрыто тестами | `backend/app/calc/costing.py` |
| Прогнозный курс: форвард, тренд, сезонность, эксперт, веса, историческая волатильность, фиксация курса | готово, тесты | `calc/fx_forecast.py` |
| Денежный поток, кассовый разрыв (величина, дата, длительность), стоимость денег, комиссии, гарантии | готово, тесты | `calc/cashflow.py` |
| Сервис до наработки: регламенты, выполнения, работы, выезды по месяцам, ЗИП, резервы | готово, тесты | `calc/service.py` |
| Статусы, переходы, задачи с SLA, многоступенчатая визация как данные, возврат, сброс виз | готово, тесты | `core/workflow.py` |
| Роли, матрица прав, серверная фильтрация полей | готово, тесты | `core/roles.py` |
| Импорт RFQ (RU-ZH, коды полей, метка L, ЗИП, ошибки, версия шаблона), справка по цене | готово, тесты; шаблон v1 генерируется кодом | `services/rfq_import.py`, `rfq_template.py` |
| Excel-расчёт: 10 листов, живые формулы, версия менеджера | готово, тесты | `services/excel_export.py` |
| КП по бренд-буку (DOCX) с проверкой утечки себестоимости | готово (python-docx), тесты; DOCX-шаблон с плейсхолдерами — очередь 2 | `services/kp_generator.py` |
| Схема БД (PostgreSQL), неизменяемость журнала и версий | модели готовы; alembic-миграции — при старте разработки | `models/`, `migrations/` |
| REST API по всем блокам | написан (см. docs/API.md), **не прогонялся на живой БД в этой среде** | `api/` |
| OIDC (Entra / Яндекс / Keycloak) + dev-режим, сессии 8 ч | написан, требует проверки на тестовом тенанте | `core/auth.py` |
| Адаптеры хранилища/почты/мессенджера/курсов | интерфейсы и local/console реализации; SharePoint — вызовы Graph без прогона; Яндекс Диск, S3, Outlook, WeCom — заглушки с контрактом | `adapters/` |
| Фронтенд: список/доска/задачи/клиенты/настройки, карточка сделки, блоки логиста и сервиса, экран КД с живым пересчётом и графиком потока | написан (React + TS), типы проверены; сборка не выполнялась | `frontend/` |
| Docker Compose, резервные копии 90 дней | готово | `docker-compose.yml` |

> Среда, в которой готовился каркас, не имела доступа к PyPI/npm, поэтому FastAPI/SQLAlchemy-слой и сборка фронтенда проверены статически (компиляция, импорт с заглушками, tsc со стаб-типами), а не запуском. Первый шаг команды — `docker compose up`, `pytest`, `npm run build` и устранение мелких несостыковок.

## Очередь 2 — Коммуникации (1–2 мес.)

* Генератор КП по DOCX-шаблону с плейсхолдерами (docxtpl), логотипы и шрифт Intro из настроек, PDF через LibreOffice.
* Outlook: черновик с вложением через Graph, отправка из системы от имени менеджера, чтение общего ящика (решить: sales@ или ящики менеджеров), привязка писем по номеру сделки к ленте и папке 06.
* WeCom: корпоративное приложение, уведомления, чат с внешними контактами заводов из карточки, сохранение файлов из чата в папку сделки и предложение импорта RFQ.
* Мобильный сценарий: статусы, визы, уведомления, фото/файлы; биометрия через M365.
* Карточка клиента с воронкой и историей КП (каркас готов).

## Очередь 3 — Аналитика (1–2 мес.)

* План/факт: ввод факта по ролям, отчёт по сделке (каркас готов), закрытие ФД, накопление факта в истории, сводный отчёт точности оценок, точность прогнозов курса по горизонтам 30/90/180.
* REST API для 1С (выгрузка утверждённых сделок, справочники, загрузка факта), вебхуки.
* Китайский интерфейс: вынос строк в ресурсные файлы, ZH-поля справочников.
