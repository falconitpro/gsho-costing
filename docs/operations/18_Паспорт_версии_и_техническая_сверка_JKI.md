## 2. База данных (шаги 3–4)

- **PostgreSQL:** 16 (образ `postgres:16` в docker-compose; локальная проверка — 16.15).
- **Как меняется схема на рабочем сервере.** Alembic **не используется**: старый комментарий в `db.py` устарел и исправлен этим PR.
  - Рабочая база перенесена со стенда 11.11.2026 (D-058). На стенде в режиме dev схема строится из моделей: `create_all` и добавление недостающих столбцов.
  - Дальше схема рабочего сервера меняется только новыми файлами `backend/migrations/NNN_*.sql`. `deploy/production/update.sh` накатывает их после резервной копии и останавливается, если изменён уже применённый файл.
  - Сейчас файлов 52: 001–051 и 016b.
- **Резервные копии.**
  - Перед каждым обновлением и ежедневно по таймеру: restic, хранилище — Yandex Object Storage.
  - Проверка восстановления — `deploy/dr/drill.sh` (режим `APP_ENV=recovery`).
  - Перед J/K/I отдельную копию делать не нужно: каждое обновление само делает копию и без неё не продолжает.
- **Сверка «модели в коде ↔ схема».** Новый скрипт `backend/scripts/schema_check.py` только читает системный каталог и ничего не исправляет. Сравнивает таблицы, столбцы, типы, NULL, внешние ключи, уникальность, индексы, лишние таблицы и столбцы.
  - Локальная база dev: 132 таблицы, 2087 столбцов, 237 внешних ключей. Расхождений, влияющих на работу, нет; есть 3 различия «NULL / NOT NULL» у столбцов, добавленных без значения по умолчанию.
  - ~~Модель рабочей базы: схема моделей на 99c1b91 плюс 52 SQL-файла — расхождений 0.~~ **Вывод был неверным (исправлено 26.11, D-178).** Рабочая база перенесена дампом со стенда, а на стенде схема годами дополнялась `init_db` (`add_missing_columns`): столбцы добавлялись без NOT NULL, а внешние ключи и индексы у уже существующих таблиц не создавались. Модель «схема моделей + SQL-файлы» этого не учитывала.
  - **Факт на рабочем сервере (26.11, `schema_check`):** 107 столбцов обязательны в коде, но в базе допускают NULL; нет 5 внешних ключей (`equipment_models.proposed_by / machine_type_id / approved_by`, `factories.legal_entity_id / default_route_id`) и 6 индексов (`deals.archived_at / parent_deal_id / request_group_id / deleted_at`, `part_requests.machine_id`, `po_lines.batch_id`). Обратного опасного случая («в коде NULL, в базе NOT NULL») — 0; таблиц и столбцов не хватает 0, типы совпадают. На работу это сейчас не влияет: код всегда заполняет эти столбцы сам.
  - **Выравнивание — `backend/migrations/052_schema_align_prod.sql` (D-178).** Для каждого внешнего ключа сначала считает ссылки «в никуда», для каждого столбца — пустые значения. Добавляет ограничение только там, где данные чистые; «грязное» место пропускает с сообщением `NOTICE` и ничего не меняет в строках. Индексы — `CREATE INDEX IF NOT EXISTS`. Повторный запуск безопасен.
  - **Пробный прогон без изменений** (на сервере, до обновления): тот же файл, где `COMMIT` заменён на `ROLLBACK`, — покажет, что будет добавлено и что пропущено:
    `sed 's/^COMMIT;/ROLLBACK;/' backend/migrations/052_schema_align_prod.sql | docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T db psql -U gsho -d gsho -v ON_ERROR_STOP=1 -q`
  - **Проверка на самом рабочем сервере** (одна команда, только чтение, в выводе нет ни данных, ни секретов):
    `docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T backend python -m scripts.schema_check --short`

## 7. Решения владельца, нужные до начала K/I

1. **Персональные данные контактов (152-ФЗ):** какие поля хранить, кто видит, сроки хранения, нужно ли согласие.
2. **Совместное владение или эксплуатация машины** — разрешено или нет.
3. **Карта площадок** — Яндекс Карты (нужен ключ API) или только координаты и ссылка.
4. **Видимость клиентов** — оставить общей или ограничить по менеджеру или направлению. Это изменение прав.
5. **Роль «инженер»** (новый код роли) и кто назначает инженеров и закрывает наряд.
6. **Приложение инженера.**
   - Платформа: Capacitor (Android и iOS) или PWA; первая платформа; учётные записи Google Play и Apple.
   - Срок жизни офлайн-пакета, объём фото и видео, порядок отзыва устройства.
7. **Существующие записи применимости** — статус при переносе. Рекомендация: «не подтверждено».
8. **Справочники** работ, нормативов, допусков и SLA — есть ли исходные таблицы.
