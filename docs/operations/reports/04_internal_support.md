## 2. Объём

### Реализовано

- **Обращение из любого раздела**:
  - кнопка «Поддержка» в шапке с отметкой новых ответов;
  - «Сообщить о проблеме» на рабочем месте;
  - форма с категорией, темой, описанием, срочностью (с подсказкой для «критичной») и до 5 файлов по 50 МБ.
  - Блок «Что будет передано» показывает адрес страницы без токенов, ID последней ошибки, браузер, ОС, экран и часовой пояс. Технические данные можно отключить.
- **Мои обращения** (`/support`): вкладки «Активные», «Ждут меня», «Решённые», «Все»; таблица на компьютере, карточки на телефоне; пустое состояние с кнопкой.
- **Карточка** (`/support/:id`):
  - переписка по порядку; системные отметки отделены от сообщений;
  - файлы показаны с состоянием проверки;
  - черновик ответа не теряется при ошибке;
  - действия «Проблема осталась» и «Закрыть обращение» с подтверждением;
  - справа — сроки и технические данные.
- **Очередь** (`/support/admin`, `support_admin`):
  - KPI: новые, без первого ответа, ждут автора, просрочены, решено за период;
  - фильтры, поиск по номеру и теме; сортировка — сначала критичные и просроченные;
  - в карточке: назначение, приоритет, взять в работу, запросить данные (с обязательным текстом), решено.
- **Жизненный цикл** по `05` §4. Повтор того же перехода ничего не дублирует; недопустимый переход — 409 без уведомлений. В закрытое обращение писать нельзя.
- **Уведомления только «в системе»**, со ссылкой на обращение. Открыл обращение — его уведомления прочитаны.
- **Отключение специалиста** снимает с него обращения. Отключённый автор остаётся в истории с отметкой «сотрудник отключён».
- **Журнал безопасности**: создание, отказ в доступе, назначение, статусы, приоритет, скачивание вложений — без текста обращений.

### Не вошло

- Внутренние заметки специалиста (`05` §6 — не в первом срезе).
- Ежедневная сводка (этап 5) и подсказка ИИ (этап 6) — используют этот API позже.
- Ссылка «Сообщить в поддержку» на экране ошибки: в приложении нет общего экрана ошибки. ID последней ошибки форма подставляет сама.

`tests/test_support.py`:
- SUP-01 — номер, очистка адреса и техданных, файлы, только «в системе», проверка полей;
- SUP-02 — 20 обращений с разными номерами подряд, повтор по ключу;
- SUP-03 — 404 чужому и обычному админу, журнал без темы;
- SUP-04 — READ против EDIT;
- SUP-05 — полный цикл, 409, неизменяемость;
- SUP-06 — получатели, ссылки, без почты, прочитано при открытии;
- SUP-07 — отключение специалиста и автора;
- SUP-08 — скрипт как текст, `X-Request-ID`;
- заражённый файл — обращение не создаётся, антивирус недоступен — 503;
- SLA;
- права по умолчанию.

Браузерный сценарий:
1. менеджер создаёт обращение с файлом и темой со скриптом — показано текстом, скрипт не выполнился;
2. ЗГД назначает себя, отвечает и запрашивает данные;
3. у менеджера появляется отметка на кнопке, он отвечает — отметка исчезает;
4. ЗГД отмечает обращение решённым, менеджер закрывает;
5. на 390 px менеджер создаёт обращение и отвечает в нём.
