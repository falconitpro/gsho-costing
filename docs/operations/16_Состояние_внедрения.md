## 6. Блокировки и риски на старте

1. Актуальный main может отличаться от baseline — обязательная сверка.
2. Yandex production checks невозможны без действий владельца и секретов; не симулировать их выполнение.
3. ClamAV на 4 ГБ RAM требует измерения; fail-open запрещён.
4. Старые stateless sessions требуют контролируемого rollout.
5. Существующие тесты финансового пакета могли быть неидемпотентны на повторно используемой DB; сравнения проводить на чистой PostgreSQL.
6. Нумерация migrations может измениться в main; не перезаписывать чужие файлы. **Сработало:** 010–012 заняты, пакет использует 013–018 (D-021).
7. In-app backup alerts не заменяют внешний heartbeat при полном отказе сервера.
