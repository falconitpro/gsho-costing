## D-005 — Два Yandex SA и роли

- Решение: backup SA `storage.editor` только на выделенный bucket; restore SA `storage.viewer` только на него.
- Причина: restic требует read/list/lock/delete/prune; `storage.uploader` недостаточен, `storage.admin` избыточен.
- Дополнительно: проверить отсутствие широких inherited roles на каталог/облако.
- Статус: проектное решение.

## D-006 — Object Lock не входит в первичный rollout

- Решение: versioning включить; Object Lock и сложные lifecycle правила не включать автоматически.
- Причина: lock может конфликтовать с `restic forget --prune` и препятствовать удалению объектов до срока.
- Будущий hardening: отдельный repository/bucket test, согласование сроков и стоимости.
- Статус: зафиксировано.

## D-007 — Gate отключения Timeweb

- Решение: старый backup работает, пока не будут manual + две последовательные daily + check + полное восстановление на recovery-ВМ + явное подтверждение владельца.
- Только затем: удалить Compose service, владелец вручную отключить provider backups, контролируемая очистка старых архивов.
- Запрещено: `docker compose down -v`, автоматическое удаление volumes.
- Статус: обязательный gate.

## D-008 — Наблюдаемость backup

- Решение: атомарный host `last-run.json` + sanitized `BackupRun`, in-app failed/stale alerts.
- Ограничение: при полном падении сервера in-app alert недоступен; внешний heartbeat рекомендован, но не заявлен реализованным.
- Статус: проектное решение.

## D-009 — Server-side sessions

- Решение: JWT получает `sid`, каждая CRM-сессия имеет AuthSession с idle/absolute expiry и revoke; logout/revoke/offboard проверяются сервером.
- Совместимость: короткий migration window, затем old stateless tokens отклоняются; постоянного bypass нет.
- Статус: проектное решение.

## D-010 — MFA и пароли

- Решение: TOTP, зашифрованный secret, recovery hashes, mfa_pending 5 минут, optional → required после подтверждения.
- Пароли: 12–128, буквы+цифры, denylist, history 5, temporary must-change, старые hashes поддерживаются.
- Hash cost повышается после benchmark; обязательная смена каждые 90 дней не вводится.
- OIDC MFA принимается только при подтверждённых amr/acr/политике.
- Статус: проектное решение.

## D-011 — Offboarding без удаления истории

## D-025 — Часовой пояс таймера задаётся в OnCalendar

## D-027 — Канал статуса: только чтение каталога хоста

## D-028 — Политика хранения: одна группа на хост, постоянный путь staging

- Дата: 11.11.2026.
- Решение: `restic forget --host gsho-prod --tag gsho --group-by host --keep-daily 90 --keep-monthly 12 --prune`. Staging — постоянный каталог `<BACKUP_STAGING_DIR>/gsho-backup` под `flock`, а не `mktemp -d`.
- Причина: по умолчанию restic применяет политику отдельно к каждой группе «хост + пути». При случайном пути staging каждый снимок попадал бы в свою группу, и `--keep-daily 90` ничего бы не удалял. Тест `test_retention_daily_and_monthly` на синтетических снимках с датами это выявил и закрепил исправление. Постоянный путь под блокировкой даёт и родительский снимок для дедупликации.
- Подтверждение владельца: не требуется.
- Статус: действует.
