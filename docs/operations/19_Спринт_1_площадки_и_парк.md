# K-2. Площадки клиентов и связь с парком (D-182)

Основа — пакет владельца «BERGHAUS CRM Sprint 01 Patch K Sites v1» (база 53ce5a3, SHA-256 0bdb330b…6003). Что исправлено по сравнению с пакетом — в журнале решений, D-182.

## Что есть
- Справочник площадок клиента `client_sites`: название, тип, код у клиента, адрес, координаты, режим допуска, охрана труда, комментарий, архив.
- API `/api/clients/sites`:
  - `GET /meta` — списки типов и режимов, право правки;
  - `GET ?client_id=&q=&include_archived=&limit=&offset=` — список с числом машин и ссылкой на карту;
  - `POST`, `GET /{id}`, `PUT /{id}` — архив через `is_active=false`.
- Права — группа «Клиенты: площадки» в «Уровнях доступа». Инженер получит доступ по своим нарядам в I-1.
- Машины парка: `site_id`, `origin` (berghaus · third_party · rental · other · unknown) и `warranty_until`. Фильтр парка `?site_id=`.

## Миграция
`backend/migrations/054_client_sites_fleet.sql` — только добавление. Применяется `update.sh` после резервной копии. В CI проверяется по образцу схемы рабочей базы.

## Перенос старых площадок (только по согласованию владельца)
Пробный прогон ничего не меняет и показывает, что будет создано, и похожие названия для ручной проверки:

    docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T backend python -m scripts.sites_import

Перенос:

    docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T backend python -m scripts.sites_import --yes

- Повторный запуск ничего не дублирует.
- Исходные `clients.sites` и `client_machines.site` не меняются.
- Каждая созданная площадка и привязка машины попадает в журнал действий и реестр изменений.
