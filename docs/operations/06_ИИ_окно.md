# ИИ-окно

## 1. Назначение и безопасный первый срез

В текущую CRM добавляется drawer с диалогом, который помогает по разрешённым данным, объясняет работу системы и отвечает на общие вопросы. Первая версия **только read-only**. Модель не является пользователем, администратором или источником фактов: факты предоставляют серверные tools после проверки прав.

Переиспользовать `backend/app/adapters/llm.py` (`make_llm`). Второй SDK/adapter слой не создавать. Общий помощник настраивается отдельно от юридического LLM:

```text
ASSISTANT_PROVIDER=none
ASSISTANT_MODEL=<ЯВНО_ВЫБРАННАЯ_МОДЕЛЬ>
ASSISTANT_CONTEXT_POLICY=deny_external
ASSISTANT_HISTORY_RETENTION_DAYS=30
ASSISTANT_DAILY_REQUEST_LIMIT=<ПОДТВЕРЖДЁННЫЙ_ЛИМИТ>
```

Секрет provider остаётся в существующем protected env/secret manager. Нельзя автоматически наследовать включённый legal LLM provider и начать отправку CRM-данных. Для external provider владелец отдельно подтверждает `ASSISTANT_CONTEXT_POLICY=allow_minimized` после ознакомления с data policy.

## 2. Режимы

### `crm`

Вопрос по сделкам, оборудованию, задачам, рабочему месту и финансам. Оркестратор выбирает только разрешённые tools либо возвращает детерминированный результат. В prompt модели попадает минимальный результат tool, уже лишённый закрытых полей.

### `help`

Поиск по локальному версионируемому help index и документации CRM. Не требует внешнего LLM: keyword/structured search возвращает подходящие разделы и ссылки. Модель может только переформулировать найденные инструкции без добавления несуществующих кнопок.

### `general`

Общий вопрос пользователя. Не передаются CRM history, текущая сделка, страница, выбранные filters и tool results. Если provider off, отображается честное состояние: «Общий ИИ отключён. Вопросы по CRM и справка доступны в разрешённых разделах».

Переключатель режима виден рядом с полем ввода. При смене в general показать короткую подсказку «Контекст CRM не используется». Не смешивать незаметно режимы в одном ответе.

## 3. Архитектура запроса

```text
User + AuthSession + assistant_use
  → POST /api/assistant/messages (mode, conversation_id, text)
  → rate limit + daily quota + length validation
  → server loads conversation and verifies owner
  → intent/router (deterministic first; model router optional)
  → allowlisted tool call with server-side CurrentUser
      → effective_perms + acting_for/overrides
      → can_see_deal + finance Visibility + field filters
      → bounded DTO + source IDs/deep links
  → AiToolAudit (sanitized)
  → optional LLM receives minimized tool DTO
  → response validator: no invented sources/IDs/amount changes
  → AiMessage + citations + warnings + provider/fallback
```

Модель не получает `db: Session`, generic eval, SQL executor, file reader, HTTP client, environment или arbitrary function name. Аргументы tool валидируются Pydantic; user ID берётся из session, не из аргументов модели.

## 4. Allowlist tools

### 4.1 `deal_search`

Вход: `query`, `status?`, `limit<=10`. Выход: deal ID/номер, безопасное название, разрешённый статус, URL. Применяется `can_see_deal`; отсутствие доступа эквивалентно отсутствию записи. Не возвращать все поля сделки.

### 4.2 `deal_get`

Вход: `deal_id`. Повторная `can_see_deal`, `effective_perms`, overrides и `filter_payload`. Выход — только минимальный DTO, нужный ответу. Поля себестоимости, закупки, маржи, legal docs и attachments включаются лишь при соответствующих правах. Internal IDs, не нужные пользователю, не попадают в prompt.

### 4.3 `equipment_price_history`

Вход: нормализованное название/модель, limit, date range. Использовать существующую историю предложений/цен и проверки `factory_price_history`, cost/procurement visibility. Выход: оборудование, цена decimal string, валюта, дата, источник, supplier в разрешённом виде, deep link. Если прав нет — не «0», а отказ/недоступность без утечки.

### 4.4 `finance_obligations_summary`

Вход: направление `receivable|payable`, контрагент/deal при наличии, as_of. Использовать `finance.obligations.query`, `finance.debt.build`, `finance.overview.build`; не пересчитывать debt в новом сервисе.

Выход:

- остаток по каждой валюте отдельно, никакого сложения RUB+CNY+USD;
- подтверждённые и временно разнесённые суммы отдельно;
- юридический/финансовый срок и overdue по существующей логике;
- data quality warnings;
- ссылка `/finance` либо `/summary?kind=money` в зависимости от права;
- дата/время актуальности.

Учитывать `finance.access.Visibility`, `payment_terms`, `cost`, `factory_price_history`, `finance_section` и `finance_analytics`. Пользователь без финансовых прав не получает скрытые суммы даже обобщённо.

### 4.5 `tasks_my`

Вход: status/due window/limit. Только текущий пользователь и разрешённые acting_for, без `user_id` из модели. Выход: ID, название, срок, статус, deal link при доступе.

### 4.6 `workplace_summary`

Использовать существующий workplace DTO/выделенные selectors, уже отфильтрованные по правам. Не копировать монолитный `workplace.py` ради AI. Ограничить список, не передавать все уведомления и закрытые money blocks.

### 4.7 `help_search`

Вход: вопрос, limit<=5. Источники — локальная актуальная документация и curated help entries. Выход: заголовок, безопасный excerpt, route/anchor, version/commit. При нулевом результате честно «В справке не найдено», предложить `/support`, но не создавать тикет.

## 5. Ответы, источники и ссылки

DTO ответа:

```json
{
  "message_id": "<ID>",
  "mode": "crm",
  "text": "<ОТВЕТ>",
  "facts": [],
  "sources": [
    {"type": "deal", "id": "<ID>", "label": "<БЕЗОПАСНОЕ_НАЗВАНИЕ>", "url": "<CRM_ROUTE>"}
  ],
  "warnings": [],
  "provider": "none",
  "fallback": true,
  "generated_at": "<UTC>"
}
```

- `sources` создаётся оркестратором из tool results. Модель не может добавить свой URL/ID.
- Валюта, дата и сумма берутся из фактического DTO. Для детерминированного финансового ответа можно вообще не вызывать LLM.
- Если модельный текст противоречит facts или validator обнаруживает неподтверждённые числа/IDs, вернуть structured fallback вместо опасного текста.
- Нельзя ссылаться на «базу CRM» без конкретного разрешённого источника.
- Deep link ведёт на существующий route; при открытии права проверяются снова.
- Для неоднозначного «сколько должны» сначала уточнить «заказчику или нам заказчик?»/направление и контрагента, если контекст не определён. Не угадывать.

## 6. Примеры поведения

### Цена оборудования

Найдено 3 разрешённых предложения: показать диапазон и конкретные строки с датой/валютой/источником. Не выводить «среднюю рыночную цену», если данных недостаточно. Если часть скрыта правами, не сообщать скрытое количество как факт; можно сказать «показаны доступные вам записи».

### Долг

«По доступным финансовым данным на 11.11.2026 остаток нашей задолженности заказчику X: … по валютам… Расчёт: обязательства и фактическое исполнение. Подтверждено… временно разнесено… Открыть Финансы». Если финансового права нет: «У вас нет доступа к финансовым обязательствам. Обратитесь к ответственному» без суммы.

### Как выполнить действие

Help-search возвращает существующие шаги и ссылку. Если UI изменился, help entry обновляется в том же PR; модель не придумывает «синюю кнопку справа».

### Нет данных/ошибка provider

Сохранить вопрос и технический fallback по политике истории. Показать retry; не создавать бесконечные повторные external calls. CRM deterministic tools/help продолжают работать.

## 7. Права и приватность

- `assistant_use=READ` по умолчанию всем активным ролям; individual override может закрыть.
- `assistant_admin=EDIT` ЗГД: quotas/retention/provider status и технические counters, но не чтение чужого содержимого по умолчанию.
- Диалог доступен только `owner_id`. Support admin, security admin, обычный admin не получают текст автоматически.
- `AiToolAudit` содержит sanitized args/counts/IDs, не полные результаты. Security audit видит технические события вызова без prompt/response.
- В общий `AuditLog` не писать полный prompt/response. Не хранить chain-of-thought, hidden instructions, provider API key.
- Перед external call минимизировать поля и удалять secrets/токены/подписанные URLs. Не отправлять содержимое закрытых документов в первом срезе.
- Удаление диалога: soft delete, исключение из выдачи и фоновое удаление содержимого по retention; sanitized audit остаётся. Retention job не удаляет бизнес-данные.
- Экран первого использования объясняет: что видит помощник, используется ли внешний provider, срок хранения и запрет ввода секретов.

## 8. Лимиты и надёжность

- текст запроса: например до 4000 символов; tool result ограничен размером/числом записей;
- история: последние N сообщений и token budget, не вся БД;
- per-user/minute rate limit и атомарная daily quota; admin limits только server config;
- timeout external provider, ограниченные retries только на безопасных ошибках; не списывать повторно quota дважды за retry одного logical request;
- circuit breaker при серии ошибок; fallback не скрывает outage;
- background retention и cleanup не выполняются на каждом HTTP request;
- логи metrics: latency, tool, result status, token usage, без prompt content.

## 9. API

- `GET /api/assistant/status` — enabled modes, provider configured/off, policy/retention без secrets;
- `GET /api/assistant/conversations` — свои;
- `POST /api/assistant/conversations` — создать;
- `GET /api/assistant/conversations/{id}` — владелец, paginated messages;
- `DELETE /api/assistant/conversations/{id}` — владелец;
- `POST /api/assistant/messages` — отправить вопрос;
- `POST /api/assistant/messages/{id}/feedback` — владелец сообщения;
- `GET /api/assistant/admin/metrics` — assistant_admin, агрегаты без содержимого.

Чужой conversation/message — 404. `assistant_use` отсутствует — 403 без provider call. Не передавать client-supplied provider/model/API key как рабочую настройку.

## 10. UI

Drawer справа ~420 px на desktop, full-screen на mobile:

- заголовок «Помощник CRM», режим, статус provider;
- список сообщений, источники под ответом, warnings;
- поле ввода, Enter отправляет, Shift+Enter новая строка;
- stop/retry только если реально поддержаны backend;
- кнопки «Новый диалог», «История», «Удалить диалог» с подтверждением;
- быстрые вопросы ведут к реальному submit: «Что требует моего решения?», «Как создать обращение?»;
- ссылка «Открыть поддержку» — настоящий route;
- loading не блокирует остальную CRM, drawer закрывается Esc с сохранением черновика локально без sensitive persistence по выбранной политике;
- ошибки/пустая история/лимит/fallback имеют отдельные состояния.

Никакого write CTA «Оплатить», «Изменить права», «Закрыть сделку» в первом срезе.

## 11. Тесты

- каждый tool с ролями ЗГД, admin, менеджер, наблюдатель, без финансового права, с overrides и acting_for;
- IDOR на conversation/message/tool deal;
- модель пытается указать другого user, arbitrary tool/SQL/path — отклонено;
- закрытые поля отсутствуют в provider mock payload;
- источники только фактические, unknown ID удалён;
- CNY/RUB не складываются;
- debt совпадает с `finance.debt.build` на одних synthetic fixtures;
- provider off/timeout/invalid response даёт fallback;
- help работает без LLM;
- quota concurrency не позволяет превысить лимит;
- retention/delete скрывает содержимое;
- mail/WeCom не вызываются;
- UI 390/768/1280/1440, keyboard, loading/error, реальные переходы по citations.
