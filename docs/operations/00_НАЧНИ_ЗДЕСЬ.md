## Несгибаемые ограничения

### Код и существующая CRM

- Не создавай standalone app, второй React-проект, новый backend, Tailwind, shadcn/ui или новую дизайн-систему.
- Сохраняй существующие маршруты, модели, ответы и бизнес-правила. Изменения схемы только аддитивные; не удаляй и не перезаписывай существующие данные.
- Сохрани текущий визуальный язык: `--accent: #ff3131`, `--bg: #fafafa`, белые карточки, `.card`, `.tabs`, `.badge`, `.btn`, `.page-head`, `.section-head`, `.kpi`, существующие `NotificationBell`, `InfoBar`, `FloatingScrollbar`.
- Не переносить в CRM рекламную тему страницы входа, минеральную текстуру и Noto Sans как новую корпоративную тему.
- Не скрывай закрытые данные только в React: сервер не должен их возвращать. Используй `can_see_deal`, `finance.access.Visibility`, эффективные права, overrides и `filter_payload`.

### Миграции, деплой и данные

- Новые change set’ы продолжают текущую нумерацию после `009_mirror_parts_rfq.sql`: `010`–`015` по карте из `02` и `08`.
- SQL должен быть аддитивным, транзакционным там, где PostgreSQL это поддерживает, с `IF NOT EXISTS` для повторного безопасного применения. Проверь двукратное применение и соответствие моделям.
- Не запускай production deploy, production migration, seed, restore или destructive migration без отдельного явного подтверждения владельца.
- Не используй production-дамп в обычном dev/test и не передавай реальные данные в Claude или другие ИИ-чаты. Тесты — на синтетических данных.
- Restore rehearsal разрешён только в изолированном recovery-контуре по `13`; это не общий тестовый стенд.
- Не выполняй `docker compose down -v`, не удаляй Docker volumes и не отключай provider backups в Timeweb автоматически.
- В `deploy/deploy-remote.sh` нельзя оставлять безусловный production seed. Pre-deploy backup включается только после успешной настройки Яндекса; до настройки он не должен внезапно блокировать обычный deploy.

### Секреты

- Не выводи и не сохраняй в git реальные пароли, RESTIC_PASSWORD, static secret keys, JWT secrets, MFA secrets, SMTP credentials, SSH-ключи и токены.
- В примерах только `<…>`-заглушки. Не используй выдуманные значения, похожие на настоящие секреты.
- Не помещай секреты в shell history, Command-line arguments, screenshots, `manifest.json`, отчёты, логи или ZIP. Переменные считываются из защищённого `EnvironmentFile` либо secret manager.
- Не пиши секреты в `SecurityEvent`, `AuditLog`, `AiMessage`, `AiToolAudit` и support attachments.

### Яндекс и отключение Timeweb

- Основной постоянный адрес копий — приватный Yandex Object Storage bucket; клиентское шифрование `restic` обязательно.
- Ежедневный timer: `*-*-* 19:00:00`, `Timezone=Europe/Moscow`, `Persistent=true`, без исключения выходных.
- Используй `pg_dump --format=custom`, manifest, SHA-256, проверку `restic snapshots` и `restic check`.
- Не включай Object Lock одновременно с непроверенным `restic forget --prune`. Сначала отдельный тест совместимости; блокированные объекты нельзя удалить раньше срока.
- Gate отключения Timeweb: минимум две успешные последовательные ежедневные копии, проверка целостности, полное восстановление БД и вложений на чистой recovery-ВМ, явное подтверждение владельца. Только затем удаление старого Compose `backup` и ручное отключение provider backups владельцем.
- Временный staging на Timeweb удаляется после успешной загрузки; постоянных локальных копий после перехода не остаётся. Небольшой status/log без данных — не резервная копия.

### Поддержка и ИИ

- Для поддержки не подключай `adapters.mail`, SMTP, DNS и Яндекс 360. Используй только `NotificationLog(channel="app")`; общий `notify()` может инициировать другие каналы пользователя, поэтому для support создай app-only helper.
- Сотрудник видит только свои обращения. `support_admin` — отдельное право; роль admin сама по себе не раскрывает содержимое чужих обращений.
- Модель не получает прямой доступ к БД и не выполняет произвольный SQL. Разрешены только server-side tools из `06`.
- Каждый tool повторно проверяет пользователя и объект. Финансовые ответы используют `services/finance/obligations.py`, `debt.py`, `overview.py`, `cashview.py`; никакой параллельной финансовой формулы.
- Первая версия ИИ только читает. Платежи, смена прав, договоры, расчёты, отключение сотрудников, создание/закрытие задач и любые write actions запрещены.
- Цитаты и ссылки формируются из фактических tool results, а не придумываются моделью. Нет данных — честный ответ «не найдено».
- Провайдер общего помощника по умолчанию `none` и настраивается отдельно от юридического ИИ. Сводка и help-search работают без модели.

## Критерий готовности всего пакета

Пакет считается внедрённым только когда:

- все пять блоков доступны в текущей CRM и не ломают существующие функции;
- пройдены ролевые, API, миграционные и браузерные проверки из `12`, включая 1440, 1280, 768 и 390 px;
- отсутствуют мёртвые CTA, ошибки консоли и неожиданные 4xx/5xx;
- Яндекс-копии и restore rehearsal подтверждены артефактами без секретов;
- Timeweb отключён только по gate и подтверждению владельца;
- журналы решений, состояние, отчёты этапов и PR-ссылки актуальны;
- в отчёте отдельно перечислены действия, оставшиеся владельцу в Yandex Cloud, Timeweb и production.
