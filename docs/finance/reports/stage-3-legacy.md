# Отчёт о правке 2 — доступ КД и старые отметки оплаты (этап 3)

## 1. Идентификация

- Правка: (а) решение владельца «по умолчанию доступ в «Финансы» для КД закрыт»; (б) завершение этапа 3 — старые отметки оплаты и ссылка из исполнения.
- Дата: 10.11.2026. Ветка: `feat/finance-option-b-2` от `main` `961b922` (PR #117 слит).
- Решения: D-116 (заменяет D-040 в части доступа к разделу), D-117…D-120.
- Статус: **завершён**.

## 2. Impact analysis (протокол 08)

- Затронуто: матрица прав (новая группа, без изменения существующих), проверка чтения «Финансов», три старых endpoint оплаты (ответ расширен полем `finance`, прежние поля не менялись), вкладка «Исполнение», вкладка «Ликвидность и валюта».
- Не затронуто: `finance_analytics` и все экраны, которые от него зависят (сделки, карточки контрагентов, «Сводка → Деньги», рабочее место); расчётный движок; подписанные условия договоров; существующие `PlanFactEntry` (не удаляются и не меняются).

## 3. Что сделано

- **D-116**: группа `finance_section` — ФД и ЗГД «видит», КД нет. КД с правом `finance_analytics` по-прежнему видит суммы в сделках и «Сводку → Деньги». Право выдаётся в настройках уровней доступа; проверено тестом выдачи и снятия исключения.
- **D-117/D-118**: факт платёжного этапа, «оплачено» в договоре и ручной платёж план/факта → одна запись «требует сверки» без счёта; авто-разнесение — только при однозначном соответствии; повтор без дублей; снятие → отзыв; подтверждённое ФД не переписывается.
- **D-119**: сверка записи — выбор счёта и банковского номера, проведение, подтверждение разнесения; отзыв с причиной.
- **D-120**: ссылка «Платежи сделки в «Финансах»», бейдж статуса сверки у платёжного этапа, предупреждение после отметки.

## 4. Схема

- Новые колонки `finance_transactions.withdrawn_at/withdrawn_by/withdrawn_reason`; dev — `add_missing_columns()`; прод — `backend/migrations/003_finance_legacy.sql` (не запускался).
- Репетиция: 002 + 003 на схеме без финансовых таблиц → расхождений с моделями нет; 003 дважды — без ошибок.

## 6. Ограничения

- Отметка «оплачено» в карточке договора сохраняет запись сверки, но сама карточка договора предупреждение пока не показывает (оно есть в ответе API и во вкладке «Исполнение»).
- Ранее внесённые старые отметки (до этой правки) в «Финансы» не перенесены — нужен отдельный dry-run инвентаризации (02, раздел 10, шаг 1).
- Production rollout по-прежнему требует ручного применения 002 и 003 (D-100).
