## 5. План выката

Тестовый стенд `crm.dobrov.pro` работает с `APP_ENV=dev`, поэтому таблицы создаются при автодеплое. Ниже — порядок для окружения с `APP_ENV=prod`; на стенде шаги 2–3 выполняются сами.

1. **Резервная копия.** `docker compose exec -T db pg_dump -U gsho gsho | gzip > before-finance.sql.gz`, проверить размер файла.
2. **Схема.** По порядку: `psql -v ON_ERROR_STOP=1 -f backend/migrations/00{2..7}_*.sql`. Скрипты аддитивны и повторно безопасны: только `CREATE … IF NOT EXISTS`, без изменения существующих таблиц.
3. **Код.** Деплой ветки `main` обычным способом.
4. **Проверка схемы.** `python docs/finance/qa/rehearsal.py schema` → `"ok": true`.
5. **Пробная пересборка.** ФД или ЗГД: `POST /api/finance/sync?dry_run=true`. Просмотреть `skipped`, `conflicts` и `legacy_marks`.
6. **Пересборка.** `POST /api/finance/sync?dry_run=false`. Повтор того же вызова должен дать 0 созданных.
7. **Ввод данных ФД.**
   - Счета на банковских профилях компаний группы.
   - Подтверждённые остатки.
   - Импорт выписки или ввод операций.
   - Разнесение и подтверждение записей «требует сверки» в «Сверке и уточнениях».
8. **Права.** Раздел открыт ФД и ЗГД. КД — по решению владельца в настройках доступа, по умолчанию закрыт (D-116).

## 6. План отката

- **Код.** Вернуть предыдущий коммит `main` и задеплоить. Старые экраны («Сводка → Деньги», план/факт, исполнение) работают без финансовых таблиц только на старом коде. Поэтому откатывается код целиком, а не отдельные части.
- **Данные CRM.** Внедрение их не меняет (п. 3: отпечатки совпадают), восстанавливать нечего.
- **Финансовые таблицы.** Можно оставить: старый код их не читает. Полное удаление — только по отдельному решению владельца: `DROP TABLE finance_*` в обратном порядке зависимостей после резервной копии. Скрипт удаления в репозиторий намеренно не добавлен.
- **Крайний случай.** Восстановление из `before-finance.sql.gz`.
