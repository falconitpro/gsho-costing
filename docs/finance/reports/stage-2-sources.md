## Сверка источников с кодом (до реализации)

| Источник | Фактическое поле | Вывод |
|---|---|---|
| Заказ поставщику | `PurchaseOrder.payments = [{due, amount, comment, paid_on}]`, валюта — `PurchaseOrder.currency`, задаётся при подтверждении | проецируется (D-121) |
| Внутригрупповой заказ | тот же формат, `kind=intragroup` | не проецируется (D-122) |
| Логистическая партия | `Batch.payments` — нигде не заполняется и не читается, формат не задан | адаптер с явным форматом, без подстановки валюты (D-123) |
| Запчасти | `parts_deals.rows().ordered_rub` | блок без даты, только чтение (D-124) |

## Что сделано

- `project_lines()` — общая проекция для всех источников (D-125); договоры переведены на неё без изменения поведения (все прежние тесты зелёные).
- Заказы: строки графика оплат → обязательства «мы платим» в валюте заказа; «оплачено» → запись «требует сверки» с временным разнесением на строку; удалённая строка → вне итогов (история сохраняется); отмена заказа → строки исключены.
- Партии: строки с явной валютой — обязательства по сделке; без валюты — конфликт «валюта не определена», вне итогов.
- Запчасти: блок «Ожидается, срок не согласован» в календаре и обзоре.
- Календарь: фильтр по источнику, номер заказа/партии, ссылка на источник.

## Ограничения

- Изменение статуса заказа из других модулей (приёмка на складе, гарантия) пересобирает проекцию только через их вызов `_sync`; если статус меняется в обход — поможет `POST /api/finance/sync`.
- При отмене заказа запись «требует сверки» по его отметке «оплачено» остаётся — ФД отзывает её или проводит (возврат аванса — отдельная операция).
- Экрана ввода графика платежей партии в логистическом блоке нет (D-123).
