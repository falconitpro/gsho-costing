# Автоматическая приёмка (D-158)

Одна команда — всё, что проверяет CI перед отметкой «проверено»:

```bash
make acceptance          # backend (pytest) → сборка интерфейса → интерфейс по ролям и сквозные сценарии → 34 случая приёмки и ширины
make test-acceptance     # только приёмка «Пульт ЗГД и поручения»
```

Нужен стенд разработки: PostgreSQL 16, backend с `APP_ENV=dev AUTH_PROVIDER=dev` (вход заголовком `X-Dev-User`; в рабочем режиме он
выключен, и приёмка честно останавливается на S00) и frontend. Адреса — `BASE_URL`, `API_URL`, браузер — `BROWSER_EXECUTABLE`,
база backend-тестов — `DATABASE_URL` (отдельная, не рабочая).

## Что внутри `acceptance.py`

| ID | Что проверяется |
|---|---|
| S00–S01 | среда; эталонные данные прогона: сделка с маржой ≈17,5 % (выиграна), два платежа клиента в CNY просрочены на 40 дн., просроченный этап, черновик без цены, руководители направлений, временный заместитель |
| A01–A06, K01–K02 | пульт, 6 показателей (методика, период, время, качество), расшифровки = числа, маржа = карточке сделки, дебиторка и рубли справочно, группы и отдельные платежи |
| A07–A09 | руководители, состав, закрепление, замещение |
| A10–A23 | поручение сотруднику из сигнала: полный цикл, причины, файл, отчёт, права руководителя (403) и постороннего (404), перенос срока, история по порядку |
| A24–A26 | поручение руководителю, передача только своим, исполнитель не принимает (403) |
| A27–A29 | счётчики = реестр, «Все проблемы», устранённые сигналы |
| A30–A34 | ширины 1280 / 768 / 390 / 360 и карточка поручения на 390: нет горизонтальной прокрутки, ключевые действия в экране |
| AUD-01…06 | регрессия замечаний аудита |
| Z99 | уборка (поручения прогона отменены, сигналы прогона закрыты) и отсутствие ошибок страниц |

Статусы: PASS / FAIL / BLOCKED (не выполнялся — упал обязательный шаг или нет среды) / FLAKY (упал, со второй попытки прошёл; повтор
только у проверок без побочных эффектов). Приёмка пройдена только если всё — PASS; иначе код выхода 1.

Отчёт (`artifacts/acceptance/`): `summary.html`, `junit.xml`, `results.json`, `manifest.json` (коммит, версии, последняя миграция в коде),
`api-failures.json`, `screenshots/`, `traces/` (`npx playwright show-trace traces/<файл>.zip`). В CI — артефакт `acceptance-report`
(и `backend-junit`), сохраняется при любом исходе.

## Отметка «проверено» и рабочий сервер

После зелёного CI на `main` job `verified` двигает ветку `verified` на этот коммит. `deploy/production/update.sh` ставит **только**
`origin/verified`; если в `main` есть непроверенные коммиты — показывает их и ставит последнюю проверенную версию. Непроверенную — только
явно: `sudo UNVERIFIED="причина" bash deploy/production/update.sh` (причина пишется в `/var/log/gsho-unverified-deploys.log`).
