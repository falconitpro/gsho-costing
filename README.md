# Модуль расчёта себестоимости и маржинальности поставок ГШО

Реализация ТЗ от 31.10.2026: сквозной процесс «запрос клиента → себестоимость → утверждённая цена → КП»
для поставок горношахтного оборудования из КНР в РФ. Стек: **Python 3.12 / FastAPI / SQLAlchemy 2 / PostgreSQL 16**, фронт **React 18 + TypeScript (Vite)**, Docker.

```
gsho-costing/
├── backend/
│   ├── app/
│   │   ├── calc/        расчётное ядро (14 статей × 3 сценария, прогноз курса, денежный поток, сервис) — без зависимостей от БД
│   │   ├── core/        конфигурация, OIDC-вход, роли и серверная фильтрация, статусы/визация
│   │   ├── models/      схема БД (SQLAlchemy)
│   │   ├── services/    импорт RFQ, Excel-расчёт, генератор КП, настройки, версии/задачи/уведомления
│   │   ├── adapters/    SharePoint/Яндекс Диск/S3, Outlook/Яндекс 360, WeCom, ЦБ РФ — сменные по настройке
│   │   ├── api/         REST (FastAPI) по блокам ролей
│   │   └── main.py
```

## Логотип

Фирменные логотипы Berghaus лежат в `frontend/public/brand/` (основной, знак «BH», монохромный красный; с прозрачным фоном) и в `backend/app/assets/` для КП: основной — на титуле, монохромный — в колонтитуле. Заменить можно через настройки (`POST /api/admin/templates/logo`) или файлами в этих папках.

## Быстрый старт

На Mac с Docker Desktop: двойной клик по `scripts/start-local.command` (первый запуск) и `scripts/rebuild.command` (обновить из GitHub и пересобрать).

```bash
cp backend/.env.example backend/.env
docker compose up --build -d
docker compose exec backend python -m scripts.seed
# http://localhost — в dev-режиме пользователь выбирается в шапке (менеджер, логист, сервис, КД, ФД, ГД, админ)
```

Без Docker: `pip install -r backend/requirements.txt`, PostgreSQL по `DATABASE_URL`, `uvicorn app.main:app --reload` из `backend/`;
фронт: `cd frontend && npm install && npm run dev`.

Тесты ядра и сервисов: `cd backend && python -m pytest -q`.

## Сквозной сценарий (dev)

1. **Менеджер**: новая сделка → клиент → импорт RFQ (`build_rfq_template` создаёт заполненный шаблон v1 для проверки) → вариант → схема оплаты → «Отправить на расчёт».
2. **Логист**: партия (маршрут, транспортные единицы, фрахт, страховка, брокер, доставка по РФ) → по позициям: внутрикитайская логистика, ТН ВЭД (ставки из справочника), утильсбор, сертификация → «Завершить блок». Отклонение от истории > 15 % требует комментария.
3. **Сервис** (если флаг): регламенты и нормативы → «Рассчитать» → «Завершить блок».
4. **КД**: экран утверждения — 14 статей × 3 сценария, цена суммой/наценкой/целевой маржой, индикатор маржи, денежный поток и кассовый разрыв, курсы по платежам, чувствительность → «Утвердить / на визу».
5. **ФД** (маржа < 3 % или разрыв > лимита): виза. **ГД** — сумма выше лимита, отказ ФД при настаивании КД, переопределение накладных.
6. Утверждение: версия расчёта, Excel (полный — в «04 Расчёт себестоимости», версия менеджера — без себестоимости), КП (DOCX, бренд-бук BergHaus, проверка на утечку себестоимости), черновик письма.
7. **Менеджер**: «КП отправлено» → исход. После «Выиграна» — план/факт.

## Что проверено

CI на GitHub (`.github/workflows/ci.yml`) на каждый push: 26 автотестов backend — ядро расчёта, workflow и права, импорт RFQ,
Excel, КП и сквозной сценарий API на живой PostgreSQL 16 (`tests/test_api_flow.py`) — плюс сборка фронтенда. Не проверено
вручную: интерфейс в браузере против живого API и интеграции с Microsoft 365 / WeCom (адаптеры с заглушками). План — `docs/IMPLEMENTATION_PLAN.md`.
